# GreenPlanner AI — этап 4.2.1: расширенный корпус русскоязычных команд

Этот проект продолжает **этапы 4.1–4.2**, не меняя Android-приложение. Главное отличие — больше обучающих команд и **разные стили речи** (краткие, разговорные, многопредложные), а также отдельная проверка на фразах, написанных вручную.

> **Важно:** 8000 команд — синтетические примеры, полученные генератором. 120 дополнительных фраз написаны вручную автором набора и не являются реальными пользовательскими сообщениями. Для объективной проверки перед выпуском приложения всё равно понадобится новый набор из добровольно предоставленных и обезличенных пользовательских фраз.

## Состав

| Файл | Записей | На класс | Назначение |
|---|---:|---:|---|
| `data/train.jsonl` | 6000 | 600 | Обучение |
| `data/validation.jsonl` | 1000 | 100 | Выбор эпохи/гиперпараметров |
| `data/test.jsonl` | 1000 | 100 | Итоговый синтетический тест |
| `data/manual_holdout.jsonl` | 120 | 12 | Дополнительный тест для анализа переноса на менее шаблонные фразы |

10 классов намерений: `CREATE_TASK`, `UPDATE_TASK`, `DELETE_TASK`, `COMPLETE_TASK`, `GET_TASKS`, `GET_SCHEDULE`, `CREATE_REMINDER`, `FIND_PLACE`, `BREAK_DOWN_TASK`, `UNKNOWN`.

По стилям: примерно **31% коротких**, **39% разговорных** и **30% длинных контекстных** фраз. Средняя длина ~10 слов, максимальная в этом наборе ~21 слово. Это не длинные полноценные диалоги с историей: многоповоротный контекст будет отдельной задачей.

`slots` — список размеченных фрагментов. Пример:

```json
{
  "text": "напомни купить молоко после работы, когда буду около дома",
  "intent": "CREATE_REMINDER",
  "slots": [
    {"label": "TASK", "text": "купить молоко", "start": 8, "end": 21},
    {"label": "ORIGIN_PLACE", "text": "работы", "start": 28, "end": 34},
    {"label": "DESTINATION_PLACE", "text": "дома", "start": 53, "end": 57}
  ]
}
```

`start` — включительно, `end` — не включительно; проверка реальных файлов автоматически выполняется скриптом `validate_dataset.py`. В `manual_holdout.jsonl` поле `slots` пустое: эти 120 фраз размечены **только по намерению**.

## Установка на Windows

Распакуйте архив рядом с `GreenPlannerAI_Stage4_2`, не поверх старого проекта (иначе перезапишете модели и результаты эксперимента v1).

Можно использовать **уже созданное** виртуальное окружение Python 3.12 из предыдущей папки (если она расположена рядом):

```powershell
cd C:\Users\MECHREVO\AndroidStudioProjects\GreenPlanner\GreenPlannerAI_Stage4_2_1
$PY = "..\GreenPlannerAI_Stage4_2\.venv\Scripts\python.exe"
& $PY scripts/validate_dataset.py
& $PY -m unittest discover -s tests -v
```

Если папки не соседние, либо использовать локальное окружение:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-rubert.txt
$PY = ".\.venv\Scripts\python.exe"
```

## Сравнить старую модель и новые данные

### Оценить **уже обученную** RuBERT v1 на одинаковом наборе из 120 фраз

```powershell
& $PY scripts/evaluate_manual.py --model rubert --model-path "..\GreenPlannerAI_Stage4_2\outputs\rubert\model" --tag rubert_v1
```

Для старой базовой модели:

```powershell
& $PY scripts/evaluate_manual.py --model baseline --model-path "..\GreenPlannerAI_Stage4_2\outputs\baseline\model.joblib" --tag baseline_v1
```

### Обучить базовую модель на новом наборе

```powershell
& $PY scripts/train_baseline.py
& $PY scripts/evaluate_manual.py --model baseline --tag baseline_v2
```

Полученные в нашей среде ориентиры для **TF-IDF**:

| Версия | Validation Accuracy | Test Accuracy | Manual holdout Accuracy | Manual holdout Macro F1 |
|---|---:|---:|---:|---:|
| v1 (1000 train) | 49,6% | 64,0% | **65,83%** | 0,6520 |
| v2 (6000 train) | 90,4% | 91,9% | **83,33%** | 0,8093 |

Осторожно с интерпретацией: первая и вторая версии имеют **разные синтетические test**, их проценты по test напрямую не сравниваются. Столбец *Manual holdout* использует одну и ту же выборку для обеих моделей и поэтому полезнее. Однако ручные фразы также составлены автором корпуса, а не независимыми пользователями.

### Дообучить RuBERT v2

```powershell
& $PY scripts/train_rubert.py --checkpoint cointegrated/rubert-tiny2 --epochs 3 --batch-size 8 --max-length 128
& $PY scripts/compare_models.py
& $PY scripts/evaluate_manual.py --model rubert --tag rubert_v2
```

Для быстрого тестирования самого конвейера можно начать с `--epochs 1`; этот прогон не следует считать окончательным результатом. На CPU обучение 6000 примеров заметно ресурсоёмче 1000 примеров. Сохранение новой модели будет в `outputs/rubert/model` **нового** проекта, предыдущую v1 модель не перезапишет.

Проверка реальной фразы:

```powershell
& $PY scripts/predict.py --model rubert --text "Перенеси встречу с преподавателем на пятницу"
```

## Правила разметки

- `CREATE_TASK` — создать задачу, нет явного требования уведомить.
- `CREATE_REMINDER` — есть слова *напомни*, *уведомь*, *сигнал* или условие срабатывания.
- `UPDATE_TASK` — перенести/изменить уже существующую задачу, включая время.
- `DELETE_TASK` — удалить/отменить.
- `COMPLETE_TASK` — отметить выполнение (это не то же, что удаление).
- `GET_TASKS` — запрос списка дел, не требует анализа времени.
- `GET_SCHEDULE` — анализ календаря, занятости и свободных промежутков.
- `FIND_PLACE` — поиск организаций и мест (в будущем 2ГИС).
- `BREAK_DOWN_TASK` — разделить задачу на этапы.
- `UNKNOWN` — запрос вне области приложения.

Внутри `slots`: `TASK`, `DATE`, `TIME`, `PLACE`, `ORIGIN_PLACE`, `DESTINATION_PLACE`, `PLACE_TYPE`, `UNKNOWN_TOPIC`. Пока **обучение классификации игнорирует эти слоты**, они сохранены для будущей модели извлечения параметров (NER/slot filling).

## Ограничения и качество

1. 8000 строк **не равны** 8000 независимо написанным человеком запросам. Шаблоны всё ещё задают значительную часть формулировок.
2. Train/Validation/Test разделены по шаблонам и не имеют полностью совпадающих строк, но слова и предметные области повторяются, возможны семантические сходства.
3. Ошибочные или составные команды с **несколькими** действиями пока размечаются только одним намерением.
4. Датасет не обучает восстановлению контекста диалога, например «тогда перенеси её на завтра» без предыдущего сообщения.
5. Не дообучайте сеть на `manual_holdout.jsonl` после просмотра ошибок и не используйте эту же выборку как «независимый финальный тест» после целенаправленного исправления её проблемных примеров. Для следующей итоговой оценки подготовьте новые фразы.
6. Похожие слова «добавь в задачи» и «напомни» отличаются намерением. При неуверенном предсказании приложение должно **спросить подтверждение**, а не самостоятельно удалять или менять задачи.
7. Никакие конкретные пользовательские адреса или сообщения из личных аккаунтов в этот набор не включены.
